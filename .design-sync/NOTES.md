# design-sync notes — Roamance

Repo-specific gotchas. Read before re-syncing.

## This repo is an application, not a component library

`package.json` is `private: true` with no `main`, `module`, `exports`, or
`types`, there is no TypeScript, and no build emits a library. The package
shape's normal discovery — built `dist/` entry plus PascalCase `.d.ts` exports —
finds nothing here.

Consequences, all of them load-bearing:

- **`--entry design-system/entry.js` is mandatory.** Without `--entry`,
  `PKG_DIR` resolves to `node_modules/roamance`, which does not exist (npm
  will not self-install a package into its own repo). With it, the build walks
  up from the entry to the repo root's `package.json` and uses that.
- **`componentSrcMap` is what creates the component list**, not discovery.
  There are no `.d.ts` exports to scan, so the pins in `config.json` are the
  only source of component names. Adding a component means editing
  `design-system/entry.js` **and** `componentSrcMap` — two files, both required.
- **`.d.ts` contracts are weak.** They are extracted from JSDoc on plain `.jsx`,
  not from real types. Treat the emitted `<Name>.d.ts` as a hint, not a
  contract, and prefer `dtsPropsFor` if a prop matters and comes out wrong.

## Components must have named exports

The converter's entry re-exports with `export * from "..."`, and **`export *`
does not re-export defaults**. A component that is only a default export
silently vanishes from the bundle — it builds clean and then every preview
fails "Element type is invalid".

`Art` and `EstimateBadge` now export both: the named export is what the bundle
picks up, the default keeps existing `import Art from` call sites working. Any
new component must do the same.

## The design system is mostly CSS classes, not components

Only two pieces have logic worth shipping as components. Everything that makes
Roamance look like Roamance — `.btn`, `.chip`, `.card`, `.segmented`, `.field`,
`.art`, and the 34 tokens — is global CSS in `src/index.css`, reaching designs
through `styles.css` rather than through the component bundle.

This is why the conventions header matters more here than in a normal sync: it
is the only place the class vocabulary gets taught. A design agent that does not
know `.chip--risk` exists will invent its own chip.

## Work Sans is declared in the stylesheet, on purpose

The app loads it from `index.html` with a `<link>`. That tag does not exist when
`styles.css` is consumed standalone, so `src/index.css` also carries an
`@import url("https://fonts.googleapis.com/css2?family=Work+Sans...")`.

The duplication is deliberate — a design system that silently falls back to a
system font is worse than one that blocks briefly. Expect `[FONT_REMOTE]`
(informational). If `[FONT_MISSING]` ever fires instead, that `@import` was
removed.

## Two different artifacts, easy to confuse

| Path | What it is |
|---|---|
| `design-system/` | Hand-built, committed. Token previews, `theme.json`, adherence rules. Built by `npm run ds`. Readable by a GitHub design-system import. |
| `ds-bundle/` | Generated by design-sync, gitignored. The upload payload. |

Both read `src/index.css` as their source of truth. Change a token there and
run **both** `npm run ds` and the design-sync build, or the two disagree.

## Known render warns

Triaged as legitimate. A re-sync printing these is *not* reporting something
new; anything outside this list is.

- **`[FONT_REMOTE] "Work Sans", "Inter"`** — expected, and the remote font does
  load. Verified with playwright against the built preview:
  `document.fonts.check('400 12px "Work Sans"')` returns `true` and the Work
  Sans 400 face reports `loaded`. "Inter" appears only as a fallback-stack
  entry in `--font`; nothing renders in it.

## A bug the render check caught

`.chip` and `.estimate-badge` are `inline-flex`, which sizes them to their
content — until they are a direct child of a flex COLUMN. `.stack` and
`.card__body` are both columns, and their default `align-items: stretch`
widened a chip to the full column, so a 97% match score rendered as a coral
bar across the whole card.

Fixed with an `align-self: flex-start` rule scoped to those two containers.
Rows are deliberately excluded — `.row` centres on purpose and the rule would
break that. Only visible by looking at a render; no check flags it.

## Re-sync risks

- **A new component silently missing.** Discovery cannot find it; it must be
  added to `design-system/entry.js` and `componentSrcMap` by hand. Nothing
  warns you.
- **A component that reverts to default-only export** disappears from the
  bundle with no build error. Check the bundle's export list if previews start
  failing "Element type is invalid".
- **`Art` is a deliberate stub.** It renders the stripe placeholder for every
  motif by design (see `docs/ASSETS.md`). Its preview is *correct* looking
  abstract — do not "fix" it. When real motifs land, its preview needs
  re-authoring to sweep them.
- **The font is fetched over the network at render time.** Offline rendering
  falls back to the system stack.
- **Weak `.d.ts`.** Any prop type that matters should be spot-checked after a
  re-sync rather than trusted.
- **Upload has never run from this machine.** `config.json` has no `projectId`:
  DesignSync needs design-system authorization, and `/design-login` cannot run
  in a non-interactive session. The next run is still a first-time sync — it
  will create the project and record the pin.
