## The central fact: two workstreams, zero contact

The design session and the code session ran **inside the same hour and never
saw each other's output**. The design session's own README states why — it
synced at 20:02, when the repo contained nothing but a README, so it authored a
product from scratch rather than from the code.

By 21:06 the repo therefore contained two incompatible descriptions of the same
app, both confident, both dated the same evening:

- **The code**: constraints form → 5-question quiz → ranked deck → true-cost card with a Hack Stack.
- **The design**: vibe boards → swipe refine → filtered results → Stay/Interests/Fly tabs → end-to-end booking.

Nobody noticed for a week. That divergence became the first thing the 22
September session had to resolve.

## What the scaffold session actually decided

The commit shipped a complete, working engine: `scoring.js`, `cost.js`,
`bio.js`, `storage.js`, `tripReducer.js`, 10 trips with itemised costs and 3–4
hacks each, a 5-question quiz, and the full token layer in `index.css`. Only
`Landing.jsx` was built; the other screens were left as deliberate
`NotBuiltYet` placeholders rather than blank pages.

The quality bar is high and consistent — heavy explanatory comments aimed at a
team learning React, a documented `store inputs, derive outputs` rule, and
`localStorage` access wrapped in `try/catch` on every path.

Four reversals inside one session, all in the direction of *less* machinery:
dropping a framework, a type system, a CSS framework, a router, and an entire
asset pipeline. Every one of them removes setup cost from a team of beginners
working in a single class session. That is the shape of a human steering toward
"what can we actually finish", not an agent optimising for completeness.

**The banner is the most useful thing the session produced.** An agent that had
just invalidated seven documents chose to say so in the file every future agent
reads first, and to name which source of truth to trust instead
(`src/lib/types.js` and `src/data/trips.json`). Without it, the 22 September
session would have started by building against Next.js docs.

## Directly evidenced prompting

`RESEARCH-LOG.md`'s three entries from this day each carry a "Rejected AI
suggestions" line. These are the only places a human decision is recorded
verbatim rather than inferred:

- **Live flight-price integration — rejected.** Credential, latency and
  correctness risk, and invisible in a two-minute demo.
- **Runtime LLM bio generation — rejected.** Hallucination risk; bios are
  pre-authored instead.

Both rejections hardened into constraints 3 and 4 in `CLAUDE.md`, and both
still hold. A rejected suggestion that becomes a written constraint is the
cheapest kind of decision to keep — nobody has to re-argue it.

## What this session got wrong

1. **It never reconciled with the design session.** Both halves were running
   in the same hour. Nothing checked.
2. **It left seven documents lying.** The banner is honest, but a banner is a
   promise to fix something later, and "later" was a week.
3. **The scaffold was never pushed.** `e3eb173` sat on one laptop. Teammates
   could not build against an engine they could not see — and one of them
   uploaded a design bundle to the same repo forty minutes later, unaware.
4. **A latent scoring bug shipped.** Budget fit was
   `1 - |sensitivity - friendly| / 5`, which penalises a trip for being cheap.
   The 5-question quiz only ever emitted `budgetSensitivity` 0 or 5, so it hid
   at the extremes for a week. See [2026-09-22](2026-09-22.md).
