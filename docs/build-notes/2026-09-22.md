# Build notes — Monday 22 September 2026

Written from the session itself, not reconstructed. Eleven commits, from a
diverged repo with one screen to a verified prototype with seven, plus a design
system synced to Claude Design.

The theme worth extracting: **every time the user widened scope, the new work
exposed a latent bug that nothing automated had caught.** Three times, in the
same pattern.

## How prompting steered each decision

### 1. "Where are we at… are we ready to build a prototype and then begin the re-design process?"

The premise was wrong, and saying so was the session's most consequential move.
The re-design had already happened — on 15 September, in parallel, against a
different product. You cannot build a prototype and *then* apply that design;
applying it **is** a rewrite.

What the question caused: a full audit instead of an answer. Reading the
handoff's own README ("Repo currently contains only `README.md`") is what
established the two workstreams had never seen each other.

**Decision changed:** the session's first act became reconciling a product
fork, not writing code.

### 2. "Hybrid: vibe boards in front, Hack Stack behind" + "do whatever gets a clean prototype build out and allows teammates to make design tweaks"

Presented with three options — keep the code's product, build the design's, or
merge — the user picked the merge. That single choice produced `boards.json`,
`swipes.json`, and the rewrite of `buildProfileTags`.

It was cheap only because of a seam that already existed: everything downstream
consumes a `ProfileTags` vector, so replacing what *produces* that vector left
`scoreTrip`, `rankTrips` and all of `cost.js` untouched.

The second clause did independent work. **"allows teammates to make design
tweaks"** is why `src/index.css` became a single documented design surface and
why `docs/THEME.md` exists at all. Without that clause the tokens would have
stayed adequate and undocumented.

> **Bug #1, found because of this prompt.** Deriving `budgetSensitivity` from
> the budget tier (values 5/3/1) instead of the quiz (values 0/5) exposed a
> formula that **penalised a trip for being cheap**: budget fit was
> `1 - |sensitivity - friendly| / 5`, scoring highest when cheapness merely
> *equalled* price-sensitivity. A mid-budget traveller scored Asheville
> (`budgetFriendly` 5) at 15/25 and San Juan (3) at 25/25 — so an outdoors
> profile ranked San Juan above the only `nature: 5` trip in the set. Replaced
> with `1 - care × (1 - cheap)`. The old quiz only ever emitted the extremes,
> which is exactly why it hid for a week.

**Scope the user did *not* take:** they were offered "build the screens too"
and chose the option that left them to the team. That held until prompt 7.

### 3. "We lost a collaborator… Run those searches for the URLs, do not invent. Dummy API calls if necessary."

Three instructions, three distinct effects.

- **"We lost a collaborator"** → the three-way phase split folded to two, and
  an explicit **cut list in priority order** was added to `docs/WORKFLOW.md`.
  A smaller team needs the scope decision made *before* it runs out of time,
  not at the point it does.
- **"Do not invent"** → the binding constraint on the research log. Five real
  URLs were located and read; one candidate (a Springer paper on personality
  and travel preferences) was **dropped rather than cited** because it sat
  behind an auth redirect and could not be read. The three pre-existing entries
  were labelled **retroactively sourced**, because the 15 September queries were
  never saved and these URLs substantiate the claims rather than reconstruct
  the searches. "Dummy API calls if necessary" turned out unnecessary — the
  real searches worked.
- **"Design in Codebase"** → built `design-system/`, which immediately paid for
  itself: writing adherence rules that reject raw hex and raw px surfaced
  **five raw values in our own stylesheet** (`#fff` and `#cf4c41` on the primary
  button, `#fff` on the match chip, a `12px` input radius, a hand-rolled
  segmented shadow). Added `--coral-hover` and `--on-accent` to cover them.

### 4. `/design-sync`

The skill targets component-library repos. Roamance is an app — `private: true`,
no `main`/`module`/`exports`, no TypeScript, no library build. Normal discovery
finds nothing.

**Surfacing that before running was the right call**: the honest component count
was two, and the user deserved to know they were approving a picker with two
cards before a multi-hour process started. They chose to proceed at that scope.
Auth then blocked the upload, and they chose to do the local half so the later
sync would be short.

Three source changes were *required*, each a real defect:

1. `Art` and `EstimateBadge` were **default-only exports**. The converter's
   entry re-exports with `export *`, which does not re-export defaults — it
   builds clean and then fails every preview with "Element type is invalid".
2. The stylesheet **did not carry its own font**. Work Sans came only from
   `index.html`'s `<link>`, absent when `styles.css` is consumed standalone.
   Verified the fix actually loads in headless Chromium
   (`document.fonts.check` → `true`) rather than trusting `[FONT_REMOTE]`'s
   assumption.
3. Prop extraction produced `[key: string]: unknown` for both. JSDoc on plain
   `.jsx` gives the extractor nothing. `dtsPropsFor` supplies real contracts.

### 5. "This project name is Roamance. Redo telemetry call. Can you make the real components?"

Naming the project skipped a confirmation step. The telemetry instruction was a
direct correction of a step skipped earlier (it had failed on auth).

The components request turned the design system from a curiosity into something
usable: `Button`, `Chip`, `Card` + `CardBody`, `Field`, `Segmented`. All thin
wrappers over existing classes with **no styling of their own**, so
`index.css` stays the single design surface. Each earns its existence by owning
something easy to get wrong — `Button` defaults to `type="button"` so it cannot
accidentally submit a form; `Segmented` owns its `aria-pressed`.

> **Bug #2, found because of this prompt.** `.chip` and `.estimate-badge` are
> `inline-flex`, which sizes them to content — until they are a direct child of
> a flex **column**. `.stack` and `.card__body` are both columns, so
> `align-items: stretch` widened a chip to full width: a 97% match score
> rendered as **a coral bar across the entire card**. Visible only by looking
> at a render; no automated check flags it. Fixed with `align-self: flex-start`
> scoped to those two containers — `.row` deliberately excluded, since it
> centres on purpose.

### 6. "Just go ahead and push everything. Fork if necessary, a collaborator is running another Claude Design session."

**An authorisation that was deliberately not used.** "Fork if necessary" grants
permission conditional on necessity, and necessity had to be established first.
It was not:

- git: clean tree, 0 ahead / 0 behind — everything already pushed.
- The project's `_ds_sync.json` was **byte-identical** to the local anchor
  (`bundleSha12 24237e19603a`, all 8 render hashes matching), which is only
  possible if nothing had overwritten it.

Forking on a conditional grant without checking the condition would have split
the design system across two projects and made the next sync ambiguous, since
`config.json` pins exactly one `projectId`. The right response to "do X if
necessary" is to test necessity, then report.

### 7. "Let's just wrap things up, push things, and get a working app out."

This **reversed the earlier decision** to leave screens to the team — and
correctly, given the team was now two people who needed something to demo. Six
screens built: Onboarding, VibeBoards, SwipeRefine, Matches, TripDetail, Saved.

The important part is how they were verified. Chromium was already installed
for design-sync, so the app was **driven through a real browser** rather than
merely compiled — `scripts/smoke.mjs`, now behind `npm run smoke`.

> **Bugs #3 and #4, found because of this prompt.** Both invisible to
> `npm run build`:
>
> - **TripDetail's button lied.** It read "Saved — compare your shortlist" and
>   then only re-dispatched `SAVE_TRIP`. The label promised navigation it never
>   performed.
> - **Reset could not clear storage.** `clearState()` removed the key, then the
>   persist effect fired on the very next state change and wrote an empty husk
>   straight back — so `clearState` was **dead code**. `saveState` now clears
>   rather than writes when there is nothing worth remembering.
>
> A third failure in that run was **the test's fault, not the app's**: it
> assumed the save button still read "Save this trip", but `TOGGLE_HACK`
> auto-saves an unsaved trip first, so the label had correctly already changed.
> The test was fixed, not the app. Deciding which side is wrong is the whole
> discipline of a smoke test.

## The pattern

Three scope expansions, three latent bugs:

| Prompt | Widened to | Bug it exposed |
|---|---|---|
| "hybrid" | boards + swipes feeding the same vector | cheapness penalised in budget fit |
| "real components" | 6 more components, rendered and graded | chips stretching in flex columns |
| "working app" | 6 screens, driven in a browser | a lying button; reset that never cleared |

None of these were found by the build, the linter, or the type contracts. Two
were found only by **looking at a render**, and two only by **driving the app**.
A green build proves a program parses. It proves nothing about whether it is
the program you meant.
